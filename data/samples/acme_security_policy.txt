ACME ROBOTICS — INFORMATION SECURITY POLICY
Version 3.1 | Effective 1 January 2026 | Owner: Office of the CISO

1. SCOPE
This policy applies to all Acme Robotics production systems, employees,
contractors and third parties handling Acme or customer data.

2. ACCESS CONTROL
2.1 All access to production systems is granted on a least-privilege basis and
reviewed quarterly by the system owner.
2.2 Multi-factor authentication is mandatory for all administrative access.
Acme enforces TOTP-based MFA on the admin console, the cloud provider console,
and the VPN gateway. SMS-based second factors are explicitly prohibited.
2.3 Shared or generic administrator accounts are prohibited. Every privileged
action is attributable to a named individual.
2.4 Access is revoked within 4 working hours of an employee's termination, and
immediately in the case of an involuntary termination.

3. DATA PROTECTION
3.1 Encryption in transit: all external traffic terminates at TLS 1.3.
TLS 1.0 and 1.1 are disabled. Internal service-to-service traffic uses mutual
TLS within the service mesh.
3.2 Encryption at rest: all database volumes, object storage buckets and
backup archives are encrypted with AES-256. Keys are managed in the cloud
provider's KMS with annual rotation.
3.3 Customer data is logically segregated per tenant by a mandatory tenant_id
predicate enforced at the data-access layer.
3.4 Production data is never copied into development or staging environments.
Test environments use synthetically generated data only.

4. PASSWORD AND CREDENTIAL MANAGEMENT
4.1 Minimum password length is 14 characters. Complexity rules are not
enforced; length and breach-list screening are used instead.
4.2 Passwords are stored using bcrypt with a work factor of 12.
4.3 Application secrets and API keys are stored in the secrets manager and
injected at runtime. Secrets are never committed to source control.

5. LOGGING AND MONITORING
5.1 Security-relevant events — authentication, authorisation failures,
privilege changes and data exports — are logged centrally.
5.2 Logs are retained for 12 months, with the most recent 90 days available
for immediate search.
5.3 Logs are write-once; application service accounts have no delete
permission on the log store.

6. INCIDENT RESPONSE
6.1 Acme maintains a documented incident response plan, reviewed annually.
6.2 Confirmed breaches affecting customer data are notified to affected
customers within 72 hours of confirmation.
6.3 A post-incident review is completed within 10 working days of resolution.

7. SECURE DEVELOPMENT
7.1 All code changes require review and approval by at least one engineer who
is not the author before merge.
7.2 Static analysis and dependency vulnerability scanning run on every pull
request. Critical and high findings block the merge.
7.3 Infrastructure is defined as code and applied through the CI pipeline.
Manual changes to production infrastructure are prohibited.
